# Kouhei AI

Kouheiさん向けの単体HTMLチャットアプリ。

**開く → https://kouheim1979.github.io/toeic/kouhei-ai/**

## iPhone・iPadでの現状（v1.0.4）

v1.0.1でもSafariのページ自体が繰り返し停止する報告がありました。原因は確定していません。iPhone・iPadでは、端末内AIの実行用コード・モデルの読み込みを停止し、外部AIの接続設定を表示します。これはページ停止を避けるための復旧対応であり、iPhoneでの会話生成が完成したという意味ではありません。

外部AIサーバーはまだ公開・接続されていません。利用には下記のサーバー設定とAPI契約が必要です。`?safe=1` を付けると他の端末でも同じ復旧表示になります。保存した会話・設定・メモは削除しません。

### 診断

`?v=1.0.4&safe=1&diagnostics=1` を付けると復旧モードの診断画面を開き、未実行の場合は低負荷診断を自動で一度実行します。保存済みの結果や中断記録がある場合は自動再実行しません。「再診断する」で手動実行できます。外部ライブラリやモデルを読み込まず、16バイトのGPUバッファーを2個使って4整数の計算結果を確認します。GPUドライバー内部の使用量まで32バイトになるという意味ではありません。この結果でLLMの動作・空きメモリー量は判断できません。

v1.0.3には、診断結果がメモリー内だけにあり再読み込みで `result: null` に戻る不具合がありました。v1.0.4では診断の実行状態・最終段階・結果・完了日時を保存します。未実行／実行中はコピー・保存を無効化し、中断時は最後の段階を共有できます。コピーの完了は診断画面内に表示し、コピーできない環境では選択可能なテキストを表示します。

診断とモデル起動の処理段階は `kouhei-ai-diagnostics-v1` に最大60件保存します。次にページを開いた際、完了記録のない処理を表示します。通常のページ移動でも未完了になるため、これだけでクラッシュとは断定しません。過去のv1.0.1のログは遡って取得できません。「診断結果をコピー」または「診断結果を保存」で共有できます。会話本文・プロフィール・知識メモ・APIキー・接続トークンは含めません。

調査で確認した関連報告：[WebLLM #753](https://github.com/mlc-ai/web-llm/issues/753)。iOS 26で大きいモデルの読み込み後にSafariのタブが終了する報告ですが、このアプリの停止原因が同一であると確定したわけではありません。実機のSafariプロセスログにはこちらからアクセスできません。

## 最初の使い方

1. ページを開き、「AIを起動する」→「モデルを読み込む」を押します。
2. 初回だけモデルをダウンロードします。Wi-Fiでの利用をおすすめします。
3. 読み込みが終わったら相談内容を送信します。「仕事」「英語」で回答の前提を切り替えられます。
4. 「自分の設定」で呼び名・仕事・回答の好みを変更できます。

v1.0.1では、端末で失敗していたBlob Workerの起動を廃止し、ブラウザー画面側で直接AIを初期化します。「実行環境を確認（モデルDLなし）」で実行用コードの取得・初期化とGPUの対応状況を確認できます。この確認だけではモデルの回答生成は行いません。実行環境の取得先が失敗した場合は別のCDNに切り替えます。エラーには停止した段階を表示します。

WebGPU対応ブラウザーとGPUが必要です。対応状況は起動時に判定し、非対応なら画面に理由を表示します。軽量モデルはQwen3 0.6B、もう一つはQwen3 1.7B。GPUメモリーの目安は約1.4〜2GB以上で、互換モードでは増えます。通信量は数百MB〜1GB以上です。小型モデルのため、複雑な推論や正確な技術判断には限界があります。

既存の言語モデルに本人向けの指示と関連メモを渡す構成です。新しい基盤モデルの学習や重みの追加学習は行っていません。Web検索やChatGPTの履歴との自動連携はありません。

## 会話と知識メモ

- 会話・設定・メモは、このブラウザーのlocalStorageに保存します。端末間の自動同期はありません。
- 「知識メモ」で文章、TXT、Markdown、CSV、JSON、XLSXを取り込めます。ファイルは最大8MB、取り込む文章は1件150万文字までです。
- 発言ストックのExcelでは「発言ストック_全件」シートを優先し、「発言本文」と日時・話題などの列を読みます。数式は実行しません。Excelの書式を完全再現する機能はありません。
- 質問のキーワードと日本語の文字列で関連箇所を検索し、回答の下に参照メモを表示します。全資料を毎回読む仕組みではありません。
- 会話が長くなった場合は直近の部分をAIに渡します。端末内AIの1回の入力は1,500文字以内です。
- 「保存・バックアップ」からJSONで保存・復元できます。バックアップには個人情報が含まれます。復元は確認後に現在の内容を置き換えます。
- 端末内AIは会話を外部サーバーへ送信しません。実行用コード・モデルはCDN/Hugging Faceから取得します。
- GitHub Pagesの同じオリジンにあるページとはブラウザーの保存領域を共有します。共用端末では利用後のデータ管理に注意してください。

## 任意：OpenAIを使う

WebGPUが使えない端末や、より大きなモデルを使う場合は、付属の `server.mjs` を自分の環境で動かします。公開ページに外部AIサーバーはあらかじめ接続していません。

Node.js 22以上が必要です。追加のnpmパッケージは不要です。API利用料はChatGPTの契約とは別です。

環境変数を設定して起動します（キーやトークンはGitHubにコミットしないでください）。

```bash
# 実際の値は自分の端末・ホスティングサービスの秘密情報設定に入力
export OPENAI_API_KEY='自分のOpenAI APIキー'
export OPENAI_MODEL='gpt-6-astra'
export APP_ACCESS_TOKEN='24文字以上のランダムな接続用トークン'
node server.mjs
```

接続トークンの生成例：`node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`

同じPCで `http://127.0.0.1:8787` を開き、「AIの設定」→「外部AIサーバー」で次を入力します。

| 項目 | 設定 |
| --- | --- |
| サーバーURL | `http://127.0.0.1:8787/api/chat` |
| 接続トークン | `APP_ACCESS_TOKEN` に設定した値 |

スマホや公開ページから使う場合は、サーバーをHTTPSで公開して、その `/api/chat` URLを設定します。ホスティング環境で必要なら `HOST=0.0.0.0` と `PORT` を設定してください。許可する画面のオリジンは `ALLOWED_ORIGINS` にカンマ区切りで指定します。初期値はGitHub Pagesの `https://kouheim1979.github.io` と、ローカルの8787番ポートです。

OpenAIのAPIキーはサーバーのみで保持します。画面の接続トークンはタブのメモリーに保持し、再読み込みで消えます。外部AIには入力・直近の会話・プロフィール・関連メモを送ります。Responses APIへ `store: false` で要求しますが、プロバイダーのログ保持規定まで無効化するものではありません。サーバーには1分12回・同時2件の簡易制限があります。公開運用時の利用額はプロバイダー側でも管理してください。

## ファイル

- `index.html`：画面・設定・保存・検索・端末内LLMを含む単体アプリ。ビルド不要。
- `server.mjs`：必要な場合だけ使うOpenAI接続用サーバー。
- `tests/core.test.mjs`：保存・検索・読み込み・接続URLの検証。
- `tests/server.test.mjs`：認証・CORS・入力検証・API変換の検証（OpenAIの応答はテスト用）。
- `tests/diagnostics.test.mjs`：小規模GPU診断・結果の再読み込み・中断時の自動再実行防止・コピー制御の検証。
- `tests/startup.test.mjs`：直接起動・取得先切り替え・中止・エラー表示の回帰検証（GPUとモデルはテスト用）。

ローカルでHTMLを開く場合、ブラウザー制約を避けるため `file://` ではなく `python3 -m http.server 8000` などで配信してください。公開版はGitHub PagesのHTTPSで動作します。

```bash
node --test tests/*.test.mjs
```

モデル実行には [WebLLM](https://webllm.mlc.ai/docs/user/basic_usage.html) 0.2.85を使用します。外部接続は [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text) に対応しています。
